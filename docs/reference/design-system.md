# Design system (living doc)

<!-- Kept current as code changes — updated, not appended. Owner: ui-design-specialist. -->

The look is the **gestal.gg aesthetic**: near-black blue-tinted panels, hairline borders, top-lit gradients, serif display headings, and one warm + one cool accent. It is fully encoded in `app/globals.css` — components consume tokens and primitives, never raw values.

## Tokens (`@theme` in `app/globals.css`)

- **Surfaces:** `bg` `#080b13` · `panel` / `panel-2` · borders `border` `#1b2942`, `border-soft`
- **Text:** `text` `#e8eef6` · `muted` `#8a98ad` · `faint` `#586478`
- **Clash accents:** Hydra = warm amber-bronze (`hydra`, `-dim`, `-bright`); Chimera = steel-blue (`chimera`, `-dim`, `-bright`). Keep this pairing everywhere the two clashes appear.
- **Semantic:** `gold` / `gold-bright` (highlights), `up` green / `down` red (trends)
- **Gradients/edges:** `--grad-card`, `--grad-inset`, `--edge-hi` (glass top edge)
- **Fonts:** `font-sans` = Outfit · `font-display` = Cinzel (headings) · `font-mono` = Geist Mono

## Primitives (`@layer components`)

**All thirteen, so nobody hand-rolls one that already exists.** This list had held only
the first five for several orders, which is how a fourth hand-copy of the form-field
class got written.

- `.card` / `.card-flush` — top-lit gradient surface, hairline border, glass edge (flush = no padding)
- `.inset` — recessed metric/field container, one shade darker
- `.fill-hydra` / `.fill-chimera` — data-viz accent fills (bright → deep along the hue); data viz only
- `.btn-ghost` — the default button: bordered, `bg-panel-2/50`, uppercase `text-xs` with `tracking-[0.12em]`, gold on hover, `disabled:opacity-40`
- `.btn-accent` — the affirmative button. Carries **no background of its own** — it sets `text-bg` and expects the caller to supply the fill (`.btn-accent bg-gold` is the established pairing), so it works for a gold primary and a `bg-down` destructive alike
- `.pill-group` / `.pill` / `.pill-active` — the segmented toggle (clash switch, settings tabs). `.pill-active` is applied *in addition to* `.pill`
- `.stat-label` — the small uppercase label above a metric or form field (`text-[11px]`, `tracking-[0.14em]`, `text-muted`)
- `.skeleton` — the loading placeholder fill: a `--color-border` base with a `color-mix(in srgb, var(--color-border) 70%, var(--color-muted))` highlight sweeping across it (`@keyframes skeleton-sweep`, 1.6s), exposed as `--skeleton-base` / `--skeleton-peak`. **Fill only — geometry is the caller's** (`h-[1lh] w-24`, `h-36 w-36 rounded-full`, …), which is what lets one class mirror a text line, a donut and an avatar square. It nests its own `@media (prefers-reduced-motion: reduce)` branch that drops the animation and holds the **peak** flat, so callers never need a motion check.
  **Both stops are border-derived on purpose, and the numbers are the reason.** Measured 2026-08-13 against the two surface tops a placeholder actually sits on — `.card`'s `#0e1524` and `.inset`'s `#0b1120`: `panel-2` (the original fill) is **1.045:1 / 1.079:1**, i.e. essentially invisible, so the old reduced-motion branch — correct in the cascade, and verified to win — left a motion-averse reader with a card whose numbers had simply vanished. The base is now **1.253:1 / 1.293:1** and the peak **2.039:1 / 2.105:1**. The peak is deliberately kept below `text-faint`'s 3.05:1: a placeholder must read as a shape that is *not yet* content, so it should never be as bright as the dimmest real text on the surface. Consumers live in `components/Skeleton.tsx`; nothing else should hand-roll a grey block.
- `.skeleton-ring` — a shape modifier for `.skeleton` (`skeleton skeleton-ring h-36 w-36 rounded-full`), masking out the middle so a donut placeholder is a **ring** at `DonutSummary`'s own 62%→92% radii rather than a solid disc. A filled circle where the live chart is a bright ring is the one placeholder that reads as "the widget was removed" instead of "the widget is loading". `mask-image` is Baseline-2023; where it is unsupported the shape degrades to the filled disc, so nothing breaks.

## Patterns

- **Dialog (modal):** hand-rolled, no library. A `fixed inset-0 z-50` overlay with `bg-black/60` backdrop centers a `.card` panel (`w-full max-w-sm`). Closes on Escape and backdrop click; the dialog component mounts only while open, so unmounting resets its form state. Title is a `SectionTitle` + a `text-xs text-muted` subtitle; actions are `.btn-accent bg-gold` (with `Loader2` spinner while pending) and `.btn-ghost`; errors render `text-xs text-down` inside the panel. Reference implementation: `components/MemberHistoryTable.tsx` (`EditWeekDialog`).
- **Locked note (a write affordance the reader may not use):** the composition that
  replaces a control rather than disabling it. A `flex items-start gap-3 rounded-xl
  border border-border bg-panel-2/40 p-4` block holding a lucide `Lock` at `size={18}`
  (`mt-0.5 shrink-0 text-muted`) and a single `text-sm text-muted` paragraph. Used
  three times: `components/DataManagement.tsx` (`LockedNote`), `components/ImportPanel.tsx`
  (`ImportLocked`), and — reduced to the bare `text-xs text-muted` sentence, no box, because
  it sits inline in a table header — `components/MemberHistoryTable.tsx`. `components/AvatarEditor.tsx`
  uses the same reduced form beside the avatar. **The copy is chosen by `readOnlyReason`, never
  by `readOnly` alone**, and the two branches are not interchangeable: `"anonymous"` says *sign in*
  and links to `/login`; `"demo"` says *connect the clan database* and shows **no** login link.
  The rule is in `.claude/rules/ux.md` (four permission cells, not three) and the reasoning in
  `docs/reference/auth.md`. **Hidden, never disabled** — a disabled control still advertises the
  endpoint behind it, which is why the `/api/backup` link is absent from the tree rather than greyed.
- **Week-change pending swap (`components/WeekTransition.tsx` + `components/Skeleton.tsx`):** a `?week=` change is a server round-trip on the four async pages that read it (`/`, `/hydra`, `/chimera`, `/timeline` — `/members` is a data page but takes no week; see below), and React keeps the old tree on screen until the new payload lands — so every `?week=` push goes through `startWeekChange(week, () => router.push(…))`, a `useTransition` held by `WeekTransitionProvider` in `app/layout.tsx`.
  **There are exactly TWO week-change entry points, and both must route through it:** `components/TopBar.tsx` (the `<select>` and both chevrons) **and `components/TimelineStrip.tsx`** (the week cards on `/` and `/timeline`, which change the very same data). This doc, the task ledger and two code comments all asserted TopBar was the only one for one review cycle, and the strip shipped a bare `router.push` that produced no spinner, no placeholders and no announcement on the largest week picker on the overview page. The invariant is greppable: `grep -rn 'set("week"' components/` must return two sites, both inside `startWeekChange`. **The first of those two is optional per page**: the `<select>` + chevrons live in `WeekPicker`, a module-local component in `components/TopBar.tsx`, and the bar renders it only when a page passes `weekNumbers` and `currentWeek` (`components/TopBar.tsx:42`). Four pages do (`/`, `/hydra`, `/chimera`, `/timeline`); `/members` passes neither and gets a title + `ExportButton` only. **The guard is `weekNumbers?.length && currentWeek != null`, so it takes a *non-empty* array — which makes it a data-state guard as well as a per-page one.** On a **connected-but-empty** database all four picker pages pass `weekNumbers = []` and `currentWeek = 0` (`latestWeekNumber` returns `0` at `lib/compute.ts:46`), the length test is falsy, and they render **no picker at all**; before 2026-08-13 they rendered an empty `<select>` beside two permanently-disabled chevrons. That is deliberate and matches `.claude/rules/ux.md`'s connected-but-empty state — the fix is a first import, not a week to pick — and it is the same hide-don't-disable reflex, applied to a control that cannot move rather than to one the visitor may not use. The split exists because the three transition hooks sit above any early return — guarding them with one would be a conditional hook — and it means those hooks are not in the tree at all on a page with no week to change. `ExportButton` is outside the conditional and reads only `exportData`, so a picker-less page still exports its CSV.
  Readers take the **debounced** flag from `useWeekPending()`: the hint only appears once a change has been in flight ~120 ms (Next's own advice, `node_modules/next/dist/docs/01-app/01-getting-started/04-linking-and-navigating.md:261`) and disappears the instant it commits, so a warm sub-100 ms change never strobes. `useWeekTarget()` is the **undebounced** companion — the week now in flight, `null` otherwise — because the visible week label has to move on the click, not 120 ms later, and because it is cleared on commit a browser Back (which moves the week with no transition) can't strand a stale label. Both return their inert value outside a provider, so a component rendered in isolation is safe.
  Regions swap via `<PendingSwap skeleton={…}>`, which takes children as a **prop** — that is what keeps the swapped `ClashCard`/`DonutSummary` server-rendered and the pages server components — and carries `aria-busy`. **`PendingSwap` renders a plain `<div>`, so it becomes the grid item and the wrapped card no longer stretches**: give the swap the layout classes *and* the card (`className="xl:h-full"` on both `PendingSwap` and the `section`, on `DonutSummary` and its skeleton alike), or the row gaps. Tables can't use `PendingSwap` inside `<table>`, so they read `useWeekPending()` directly and put **that same `pending`** on the `<tbody>`'s `aria-busy` — not the narrower `showSkeleton`, which would make the two tables disagree about being busy during the empty-search carve-out below, for one identical in-flight load; each placeholder `<tr>` also carries `aria-hidden`, because `aria-busy` on a non-live container is weakly supported and a reader would otherwise walk a slab of blank rows. (Since both tables page at ten rows, the count a reader would walk is now at most ten — see **Pagination** below.)
  Feedback also appears at the control: the `Calendar` glyph becomes a spinning `Loader2` and the `<select>` shows the **in-flight** week (the chevrons step off it, so a second press advances instead of re-requesting the week already loading). The controls stay **enabled** — hide-don't-disable is a permissions rule, not an in-flight one.
  **The announcement is not at the control, though — it belongs to the provider, and that placement is the whole point.** One `sr-only` `role="status"` lives in `WeekTransitionProvider` (`components/WeekTransition.tsx`, `WeekAnnouncer`), never in `TopBar`: `/` and `/hydra` are different page components under different Next segment keys, so a region owned by the bar is unmounted and re-inserted *already holding* `Week N loaded` on every sidebar navigation, and some AT/browser pairs announce a populated live region on insertion — a spurious completion after every page change. The provider mounts once in `app/layout.tsx` and never unmounts. Its text is **derived from the requested week** (the provider cannot see a page's `currentWeek` prop) and from both flags, so there is no timer and no `setState` in an effect (`react-hooks/set-state-in-effect` genuinely does forbid it *here* — the provider holds its own `useState`, which is the case the rule can see; contrast the **Pagination** entry below, where the setter arrives through a custom hook and the rule is blind to it): empty before any week change and while a change is still under the debounce, `Loading week N…` past it, `Week N loaded` once committed — one announcement per state change, and a change that lands in under 120 ms announces the result only. **Accepted cost of the hoist:** a browser Back moves the week with no transition, so `requested` never changes and Back announces nothing; recovering that needs the forbidden effect, and Back already has no pending state of any kind. This region matters most on `/timeline`, which shows no placeholders at all, so the spinner in the week control and this announcement are the whole of the feedback there. (`/members` was the other such page until 2026-08-13; it now has no week control, so nothing can start a week change from it and the region stays silent there.)
  **What gets a skeleton is decided by the data, not by the page** — the rule a future contributor will get wrong. Only surfaces whose numbers come from a `selectedWeek` argument swap: `ClashCard` (`getOverview`), `DonutSummary` (`getKeyUsageSummary`), and the row bodies of `ClashTable` and of `PerformanceTable`'s Hydra/Chimera tabs (`getPerformance`). Everything fed by an all-weeks call must **not** swap, even when `selectedWeek` is passed to it: `TimelineStrip` and `WeeklyBarChart` take `getTimeline(ds)` and only move a highlight; `PerformanceTable`'s "Total (All Weeks)" tab is `getAllWeeksTotals(ds)` — hence the `isTotal` guard inside that component (`components/PerformanceTable.tsx:80` defines it, `:150` combines it into `showSkeleton`), which is the only place that knows which tab is open; the Black List (`components/BlackListTable.tsx`) is the newest member of that same all-weeks family — `getBlackList(ds)` takes no week argument (`app/page.tsx:50`), so the component reads no transition state at all and never swaps; and `/timeline` and `/members` ship **zero** skeletons — but for different reasons now: `/timeline` has a week control and every surface under it is all-weeks, while `/members` has **no week control at all** (its roster aggregates every week, so the selector that changed nothing was removed on 2026-08-13). Chrome that doesn't change with the week stays real and interactive during the swap — clash name and icon, `ClashCard`'s four stat captions and its "Progress" label, "Average Keys Used", table headers, search, sort, **and the pagination control** — and only the numbers go — that is what makes a half-placeholdered screen read as *refreshing* rather than *broken*, so don't "finish the job" by blanking the rest. Because that chrome is real, prefer importing it over copying it: `ClashCardSkeleton` imports the live `THEME` from `components/ClashCard.tsx`, so a renamed clash label or a swapped icon can't survive in the placeholder. The four stat captions and "Progress" are still copied strings, because `ClashCard` declares them inline in its JSX and only `THEME` is exported (`DonutSummarySkeleton` copies its labels the same way) — if a third copy ever appears, hoist them beside `THEME`.
  Shapes mirror the real geometry — `h-[1lh]` for a line of the surrounding text size (plus a `min-h-[0.75rem]` floor, since an engine without the Baseline-2023 `lh` unit drops the declaration and would collapse every bar to 0 px), the same column count and `min-w`, `Avatar`'s inline 32px for the member cell — and the row count comes from `skeletonRowCount()` in `components/Skeleton.tsx` (outgoing rows, fallback 8, cap 30), shared so the two tables can't drift. **"Outgoing rows" means the rows actually on screen, which is now one page of them** — both callers pass `view.pageRows.length` (`components/PerformanceTable.tsx:155`, `components/ClashTable.tsx:94`), never the full filtered length, or a ten-row table would be covered by a thirty-row slab. `Skeleton.tsx` itself needed no change for that: fed 0–10 it already returns ≤10. **One case overrides it: when a search box is active and already matches nobody**, the fallback would promise 8 rows the same filter will reject again, so the "No players match" row stands through the swap. A genuinely *empty week* is not that case and does get placeholders — they stand for the unknown incoming week, not the current empty one.
- **Form fields:** labels use `.stat-label`; inputs use the inline convention `w-full rounded-lg border border-border bg-panel-2 px-3 py-2 text-sm outline-none placeholder:text-faint focus:border-gold/50` (+ `tabular-nums` for numeric values). Clash-scoped field groups get a `font-display` uppercase group header in `text-hydra` / `text-chimera`. **It is a convention, not a primitive, and it is hand-copied in four places** — `components/MemberHistoryTable.tsx:190` and `app/login/LoginForm.tsx:8` both hoist it to a local `INPUT_CLS` const (identical strings); `components/DataManagement.tsx:78` and `components/ImportPanel.tsx:312` inline it. **The focus ring is the one part that varies on purpose, and it is semantic:** `focus:border-gold/50` is the default, `focus:border-down/50` marks the destructive type-`RESET` field, `focus:border-chimera/50` marks the JSON paste area (which also takes `font-mono text-xs`). Promoting this to a `.field` primitive in `app/globals.css` would collapse the four copies — a real cleanup, but it must keep the accent overridable or it flattens that distinction.
- **Ghost icon button (tables):** `inline-grid h-7 w-7 place-items-center rounded-md border border-border bg-panel-2/50 text-muted hover:border-gold/40 hover:text-gold` with a lucide icon at ~13px and an `aria-label`. Distinct from **TopBar's page-header chevron**, which is the larger `grid h-9 w-9 … rounded-lg border border-border bg-panel` (`components/TopBar.tsx:132`); don't reach for one where the other belongs.
  **The hover half has THREE forms, and which one you want is decided by how the button says "no". None of them is drift; do not "fix" any of them back to the short one.** A control that lights up gold under the cursor while refusing to act is a lie the reader has to test to disprove, so the moment a button can refuse, the hover has to be gated.
  1. **Bare `hover:` — the button is unconditionally live.** The string above, as written. Only user: the history pencil, `components/MemberHistoryTable.tsx:156`.
  2. **`enabled:hover:*` + `disabled:opacity-40` — the button carries the native `disabled` attribute.** `:enabled` matches every button that is *not* disabled, so this gates correctly only while the attribute is really there. Current user: TopBar's week chevrons (`components/TopBar.tsx:132`, `:140`) — note these are the larger `h-9 w-9` page-header variant, so they take the geometry from the paragraph above, not from this one.
  3. **`aria-disabled:opacity-40` + `aria-disabled:hover:*` resets — the button must refuse *without* losing focus.** `components/Pagination.tsx:107-110`:
     `hover:border-gold/40 hover:text-gold aria-disabled:opacity-40 aria-disabled:hover:border-border aria-disabled:hover:text-muted`.
     Reach for this whenever the "no" state is one a reader can arrive at *while the button holds focus* — the ends of a pagination range, most obviously. A `disabled` element cannot hold focus, so the browser drops it to `<body>` and the reader's next Tab restarts at the top of the document; `aria-disabled` keeps it focusable and still announces the state. The catch that makes this its own entry: **form 2 silently stops working the moment the native attribute is dropped** — `:enabled` then matches both ends and the gold hover comes back — so the gate must move to the `aria-disabled:` variant in the same change. The resets win over the plain `hover:` pair on **specificity**, not source order: `.x[aria-disabled="true"]:hover` is (0,3,0) against `.y:hover`'s (0,2,0). See `.claude/rules/ux.md`'s third hide-don't-disable case for when the choice between 2 and 3 is forced.
     **The shape is not tied to this button geometry, and it is no longer pagination-only.** `components/BenchToggle.tsx` (a `btn-ghost`, not a ghost icon button) took the same form on 2026-08-18 for an *in-flight* refusal rather than a positional one: `aria-disabled={pending}` (`:80`) plus `if (pending) return;` as the first statement of the handler (`:39`), with `btn-ghost aria-disabled:opacity-40 aria-disabled:hover:border-border aria-disabled:hover:text-muted` so that `btn-ghost`'s own `disabled:opacity-40` (`app/globals.css:86`) can no longer match. A save button is the control an admin is most likely to press twice, so it is exactly a button that can go "no" *under a focused finger* — the argument is about focus, not about permissions, which is why the in-flight case lands here and not in hide-don't-disable. **Be aware that `BenchToggle` is currently the only in-flight control shaped this way, and the repo is not yet consistent.** `grep -rn 'disabled=' components/ app/ | grep -v aria-disabled` returns ~15 native sites across `AvatarEditor`, `DataManagement`, `ImportPanel`, `MemberHistoryTable`, `app/error.tsx` and `LoginForm` — most of them `disabled={pending}`, i.e. the same in-flight case, and none of them audited for this. `app/login/LoginForm.tsx:31-39` is worth reading before you touch any of them: it hit **exactly this defect**, documents it in the comment, and paid for it with a `useEffect` that re-focuses the email field on the pending edge — a whole hook to undo one attribute. `aria-disabled` would have made that hook unnecessary. The ones inside the history modal are inside a focus trap, where the cost is smaller. So this is a per-control judgement rather than a sweep — but for a **new** control, `BenchToggle` is the shape to copy, and where a native `disabled` already needs a focus-restoring effect, converting it deletes code. (`.claude/rules/ux.md` names `components/TopBar.tsx` as the remaining native-`disabled` focus defect; that is scoped to the *positional* case — chevrons at the ends of a range — and is still accurate there. The in-flight backlog above is a separate, unfiled question.)
  Like the form-field convention above, this is a **hand-copied string, not a primitive**. Two copies of the in-table variant today — `components/MemberHistoryTable.tsx:156` inlines it, `components/Pagination.tsx:107-110` hoists it to a local `GHOST_ICON_BUTTON` const — greppable with `grep -rn "inline-grid h-7 w-7 place-items-center rounded-md" components/`. Promoting it to `.btn-icon` in `app/globals.css` is a real cleanup; it would have to keep the hover half overridable, or all three forms above collapse into the wrong one.
- **Pagination (`components/Pagination.tsx`):** one control, one page size, six tables — Clan Performance, its "Total (All Weeks)" tab, the Black List, the clash Player Breakdown, the `/members` Roster and the `/members` Benched Roster. Three exports are the contract every caller uses: **`ROWS_PER_PAGE = 10`** (`:79`), the hook **`usePagination(rows, pageSize?)`** (`:160`), and the component **`Pagination(props)`** (`:199`). A fourth, **`paginate(rows, requestedPage, pageSize?)`** (`:140`), is exported but imported by no app code — it is the clamp as a pure React-free function so it can be exercised on its own, and the hook is `useState` + `useMemo` around it. Every call site spreads the hook's return — `<Pagination {...view} onPageChange={view.setPage} itemLabel="…" label="…" />` — so the range summary's end can never desync from the slice the table drew.
  - **Placement is not stylistic.** The control is a **sibling of the `overflow-x-auto` wrapper, inside the `.card-flush` `<section>`, after `</table>`** — **never between `<table>` tags**. That is invalid HTML: React renders it, the browser hoists it out of the table while parsing, and the result looks correct in dev and detaches in odd ways later. The same mistake bounced `PendingSwap` in the week-pending order. Reference placements, each greater than its own `</table>`: `components/PerformanceTable.tsx:304`, `components/TotalPerformanceTable.tsx:198`, `components/BlackListTable.tsx:242`, `components/ClashTable.tsx:200`, `components/RosterTable.tsx:150`, `components/BenchedRosterTable.tsx:126`.
  - **The page index is clamped on read — and the rule has a second half.** `useState` holds the page the reader *asked* for; the page handed back is `min(max(1, requested), pageCount)` against the current row count (`components/Pagination.tsx:148`). **(a) A change the app makes to the reader — a week change — clamps and never resets:** page 4 of 4 quietly reads as page 2 of 2 with rows in it rather than a blank slab, and the position the reader chose survives. **(b) A change the reader initiates — search, sort, tab, filter — DOES reset to page 1**, from the event handler that caused it (`components/PerformanceTable.tsx:134`, `:190`, `:207`; `components/ClashTable.tsx:79`, `:127`). The clamp cannot substitute for (b): page 3 of 3 is still *in range* after a search narrows 30 rows to 22, so the reader types a name and is handed matches 21–22 as if the search had found two players. Read only half of this and you get a blanket never-reset, which is what shipped first and had to be corrected. The Total tab is the one surface where the narrowing arrives as a **prop**, not an event; it uses React's documented render-phase adjustment (previous value in state, compared during render) rather than an effect — `components/TotalPerformanceTable.tsx:113-117`, keyed on a `filterKey` built only from client state so a week change cannot trip it.
  - **Why never an effect: the frame, not the linter.** An effect that syncs the index down **commits and paints** one wrong frame before correcting itself; the render-phase form is discarded and re-run before anything reaches the DOM. **`react-hooks/set-state-in-effect` will not stop you** — the rule cannot follow a setter that arrives through a **custom hook's** return value, so none of the six `usePagination` consumers is guarded. Measured both ways on 2026-08-17 (through `view.setPage`: an `exhaustive-deps` warning only; with the setter destructured first: nothing new at all) and recorded in code at `components/TotalPerformanceTable.tsx:88-104`; the header note at `components/Pagination.tsx:14-17` says the same. **This entry previously claimed lint was the guardrail. It is not** — a green lint run proves nothing here, so cite the painted frame instead. (The claim is still live in this order's task ledger, which is immutable after approval; it is wrong there too.)
  - `pageCount` is `Math.max(1, …)` so an empty list is "page 1 of 1", and the component returns `null` outright at `total === 0` (`:220`) because an empty table already says so in its own body. `pageSize` is normalized (`:125`) so 0, negatives, fractions and `Infinity` cannot degenerate the arithmetic.
  - **Prev/next stay visible at the ends, and are `aria-disabled` — NOT natively `disabled`.** Staying visible is a deliberate carve-out from hide-don't-disable: that rule (`.claude/rules/ux.md`) governs **permissions**, and "you are on the last page" is a transient position, not a permission; a control that disappears at the ends makes the chrome row jump on every navigation. Dropping the native attribute is a second, separate decision: a disabled element cannot hold focus, so paging to the last page dropped focus to `<body>` and the reader's next Tab restarted at the top of the document — and the ends were untabbable. The shipped form is `aria-disabled={!canPrev}` / `{!canNext}` (`:266`, `:281`) plus a no-op guard as the **first statement** of each handler (`:263`, `:278`); because the buttons are `type="button"` with no native attribute, Enter/Space dispatch an ordinary click and the same guard covers the keyboard. The dim and the hover reset ride the `aria-disabled:` variant — see form 3 of **Ghost icon button** above. **`components/TopBar.tsx:129-144` is NOT the pattern to copy here**: it still carries the native `disabled` on both week chevrons and therefore still has the focus defect. It is where this shape was inherited from, it is unowned by any task so far, and it is a queued follow-up.
  - **A one-page table gets the summary and nothing else.** At `pageCount === 1` the button group *and* the `<nav>` around it are not rendered (`:253`) — two chevrons that can never move and a "Page 1 of 1" are dead chrome, and a "…pagination" landmark with nothing to navigate is a false promise in a screen reader's landmark list. This does **not** reverse the carve-out above: that rests on the position being transient, which is exactly what one page is not.
  - **Markup and tokens.** The outer element is a plain **`<div>`** (`:232`) carrying the `border-t`, the padding and `xl:shrink-0`; the **`<nav>`** (`:254`) sits *inside* it and wraps only the button group. That split is load-bearing in both directions: the wrapper's element type never changes, so crossing the one-page boundary cannot unmount and re-insert an already-populated live region (the hazard that moved `WeekAnnouncer` up to the provider — see "Week-change pending swap"), and the `<nav>` can vanish without taking the summary with it. Inside: an `aria-live="polite" aria-atomic="true"` range summary — `"1–10 of 34 players"` (`:243-250`) — and two `<button type="button">` with `aria-label="Previous page"` / `"Next page"` (`:267`, `:282`) either side of a `Page N of M` label. A query-only page change moves no focus and pushes no route, so without that live region a screen-reader user gets silence and different rows. Every label is `text-muted` + `tabular-nums`; **the dimmest text token is forbidden here** — at ~3.05:1 it fails AA under `html { font-size: 75% }`, and every word this control says is information the reader needs to navigate.
  - **`label?: string` is the human name of the TABLE**, not a finished aria-label — `label="Clan Performance"`, `"Black List"`, `"Player Breakdown"`, `"Roster"`, `"Benched Roster"`. Given one, the landmark becomes `"<label> pagination"` (`:255`) and the live region opens with an `sr-only` `"<label>: "` (`:248`); a label already ending in "pagination" is used as-is rather than doubled (`:225`). Omitted, the landmark is bare `"Pagination"` and there is no prefix. **Pass it whenever two of these controls can be on screen at once** — Clan Performance and the Black List are side by side at 2xl on `/`, the Roster and the Benched Roster are side by side at 2xl on `/members`, and unlabelled they hand a screen reader two identical landmarks and two range summaries naming no table. All six call sites pass one today.
  - The wrapper carries `xl:shrink-0`, live inside `ClashTable`'s retained flex column and inert everywhere else. Callers that need the bar pinned to the foot of a stretched card pass `className="xl:mt-auto"` — **all four cards that sit in a 2+1 grid**, whose `<section>`s are `card-flush xl:flex xl:h-full xl:flex-col`: `components/PerformanceTable.tsx:167`, `components/BlackListTable.tsx:79`, and (2026-08-18) `components/RosterTable.tsx:57`, `components/BenchedRosterTable.tsx:37`. **The two Roster cards took it in the same change that put them in a grid, not afterwards** — the floating-bar defect appears the moment a card becomes a grid item, so the stretch treatment is part of gridding a card, not a follow-up fix.
  - **Where the ten rows changed the surrounding layout, per surface.** The overview (`/`) no longer locks to the viewport at all: `app/page.tsx:94` is a plain `flex flex-col gap-6 p-6` and the page scrolls like every other, with Clan Performance and the Black List in a 2+1 grid that splits at **`2xl`, not `xl`** (`app/page.tsx:136`) — two of three columns at `xl` would put a permanent horizontal scrollbar under the app's main table on every 1280–1500px laptop. `/hydra` and `/chimera` keep their viewport lock (`components/ClashDetailView.tsx`, untouched), **but the Player Breakdown card inside it no longer fills that region** — it is `xl:max-h-full` + `xl:self-start` with an `xl:flex-auto` scroller (`components/ClashTable.tsx:117`, `:140`), so the card ends after its last row and the leftover band is page background, while a short viewport still caps it and scrolls internally. Anything describing that card as filling the locked area is out of date. (Reasoned from the box model and verified as far as emitted CSS; no browser in the build environment.)

  - **The 2+1 grid is now a pattern with two instances, and `2xl` is the pinned breakpoint for both.** `grid grid-cols-1 gap-5 2xl:grid-cols-3` on the container, `xl:h-full 2xl:col-span-2` on the wide wrapper, `xl:h-full` on the narrow one — copied byte-for-byte from `app/page.tsx:136-145` to `app/members/page.tsx:86-93` (Roster + **Benched Roster**, 2026-08-18). Measured for the second instance the same way as the first: at 1536px the wide column is ~944px against the Roster's `min-w-[820px]`, and the narrow column ~465px, which a two-column Player-only table clears easily; splitting at `xl` would scroll the Roster horizontally on every 1280–1500px laptop, exactly as it would on the overview. **The two wrappers keep `xl:h-full` even though the grid does not split until `2xl`** — that is the source pattern, it is inert while the grid is one column, and diverging from it would make the two instances read as different patterns. Both cards in a 2+1 grid must also carry the stretch treatment; see the `xl:mt-auto` bullet above.
- **Participation colour tiers:** one participation percentage must not change colour depending on which card it is read in, so every table that shows one uses the same three tiers — `>= 90 → text-up`, `>= 60 → text-muted`, else `text-down`. **It is hand-copied in four files, not shared**: `components/ClashTable.tsx:52`, `components/PerformanceTable.tsx:137`, `components/TotalPerformanceTable.tsx:51` (all three pre-existing) and `components/BlackListTable.tsx:56` (added with the Black List). - **Name-adjacent status marker — the bench shield (2026-08-18):** the marker an admin's
  decision puts *beside a member's name*, so a name on a poor participation table can still
  read as settled. A gold `ShieldCheck` in a wrapper that carries the accessible name, and
  the markup is **pinned byte-for-byte**, because it exists in two places and they must not
  drift:

  ```tsx
  {member.isBenched && (
    <span className="inline-flex shrink-0" role="img" title="This player is safe from the blacklist" aria-label="This player is safe from the blacklist">
      <ShieldCheck size={N} className="text-gold" />
    </span>
  )}
  ```

  **`N` = 14 in `MemberCell`, 18 beside the member page's `<h1>`, and nothing else differs** —
  the `<span>` line is identical after trim in both copies. Verified at
  `components/MemberCell.tsx:60-64` and `app/members/[memberId]/page.tsx:234-238`.
  - **`role="img"` on the wrapper is load-bearing. It is not a redundant attribute and
    deleting it silences the marker outright.** Two mechanisms have to line up, and both were
    measured in served HTML, not inferred. (1) lucide-react stamps `aria-hidden="true"` on
    every icon `<svg>` unless an a11y prop is passed, so the glyph itself is never exposed —
    you can see the attribute in this app's own output. (2) An `aria-label` on a bare
    `<span>` is *prohibited by ARIA in HTML*: `<span>` maps to role `generic`, which takes no
    accessible name, so browsers and AT drop the label. With both in force the marker was not
    faintly announced — **it did not exist for a screen reader at all**, which is the stronger
    claim this entry got wrong for one review cycle. `role="img"` is the minimum fix: it
    replaces `generic` with a role that *does* take a name, which makes the existing
    `aria-label` valid and announced. Any wrapper element that has to carry an `aria-label`
    around a lucide icon needs the same treatment — copy the whole span, not the icon line.
  - **`text-gold`, deliberately not the good-number token — this is an owner decision with a
    reason, not a palette preference.** The good-number token is what a participation ≥ 90%
    cell and a positive trend already use *in the very rows this shield sits in*, and it is
    the glyph-plus-colour the Black List's own all-clear empty state uses (that one keeps its
    token; it is a different statement). Reusing it here made the shield read as "good
    player" rather than "excused by an admin". Gold is not a performance tier anywhere in this
    app, so it cannot be mistaken for one. Do not harmonise the two shields.
  - **Insertion point: `components/MemberCell.tsx`, the fourth flex child — after the name
    `</Link>` (`:33`) and before the Former pill (`:65`).** That single insertion lands the
    marker on **all five** tables that render `MemberCell` (Clan Performance, its Total tab,
    the Black List, the clash Player Breakdown, the `/members` Roster) with **zero call-site
    edits**, because every call site already passes a whole member object — widening the
    `Pick` to include `"isBenched"` (`:20`) was the entire change. A marker that belongs
    beside *every* occurrence of a member's name goes here and nowhere else; the alternative
    is the same span pasted five times and drifting four ways. The member detail page's
    `<h1>` is **the only name surface outside `MemberCell`**, which is why there is a second
    copy at all.
  - **It is structurally invisible on the Black List, and that is why the count below
    exists.** The exclusion happens at `getBlackList`'s roster gate, before `rows` is built,
    so every member reaching a Black List `MemberCell` has the flag false by construction —
    the one card where "exempt from this list" is on-topic is the one card the shield can
    never appear on. Do not chase this as a rendering bug.
  - **Not on the avatar.** `Avatar.tsx`'s `badge` slot is bottom-centre and would collide,
    and at the `size={56}` the detail page uses, `AvatarEditor`'s camera button already sits
    over that corner. After the name collides with nothing. `shrink-0` because the name
    beside it is the element allowed to shrink.
  - **The native `title` is a recorded owner decision, not an oversight — do not "fix" it.**
    The owner chose it **after** being shown the whole trade-off: a `title` tooltip is
    invisible on touch, unreachable by keyboard, and announced inconsistently across
    screen readers. It was chosen anyway, on the grounds that this project has no tooltip
    pattern (no `Tooltip` component, no `aria-describedby`, no `role="tooltip"` anywhere)
    and the shield's meaning is not information the reader *needs* — it is a reassurance on
    a name that is otherwise unremarkable. The `aria-label` rides along at zero visual cost,
    matching the icon-only-button precedent — **and, given the two mechanisms above, it is
    the only carrier that works for a non-hovering reader, which is exactly why the role has
    to stay.** Two things follow. (a) Building a real tooltip pattern is a design order of its
    own, and it should convert **both** copies plus the Black List's participation-cell
    `title` (`components/BlackListTable.tsx:169`) in one pass — not this one span in
    isolation. (b) The owner was offered a rewrite of the tooltip sentence during the
    2026-08-18 fix round and declined; the copy is settled too. **A future contributor who
    "corrects" any of this to an accessible tooltip without being asked is relitigating a
    settled decision.**
  - Tokens: `text-gold` on the icon and nothing else — no `text-faint` anywhere near it, since
    the wrapper carries meaning rather than decoration.
- **Black List: two patterns that put the rule beside the accusation (2026-08-18).** Both live
  in `components/BlackListTable.tsx`, whose file-header invariant is that **no threshold is
  ever typed as a digit** — every number below is read off the `rule` object.
  - **The rule travels in the column header.** The Missed-weeks `<th>` reads
    `Missed weeks (under {rule.minKeysPerWeek} of {rule.maxKeysPerWeek} keys)`
    (`components/BlackListTable.tsx:136-138`), rendering `MISSED WEEKS (UNDER 3 OF 5 KEYS)`
    under the thead's `uppercase`. The definition of the accusation sits in the same row as
    the accusation, at **zero vertical cost** — the words go into a row that already exists,
    which is what let the owner's one-line card header stay one line. The `th` takes no
    `whitespace-nowrap` and the longest unbreakable token is short, so min-content width is
    unchanged and the cell simply wraps in a narrow column. **Reach for this before adding a
    subtitle:** a threshold stated only in a card subtitle is the first thing an owner asks to
    have shortened, and then the rule leaves the screen with it.
  - **A derived figure the reader cannot otherwise see gets a gated line, never an
    unconditional one.** `excusedCount` (roster members dropped by the bench) is rendered
    twice, both gated `excusedCount > 0`: a second header `<p className="mt-0.5 text-sm
    text-muted">` under the main line (`:111-116`), and a trailing clause on the all-clear
    empty state's sentence (`:222-227`). At zero the header is byte-identical to the single
    line the owner specified and the all-clear sentence is byte-identical to what shipped
    before the count existed — **which is what the live database renders today.** Singular and
    plural go through the file's own `plural()` helper ("player is"/"players are",
    "player was"/"players were"); the clause restates no threshold, because the sentence it
    hangs off already states one. The pattern generalises: when a number on screen has been
    made smaller by an invisible rule, say so *only when it has*, and word it so it never has
    to reconcile with a roster count the reader could get from elsewhere.
- **Trend indicator (`components/TrendBadge.tsx`):** one signed-percentage badge shared by every trend surface. `ArrowUpRight` + `text-up` when positive, `ArrowDownRight` + `text-down` when negative, `Minus` + `text-faint` inside the ±0.5% dead zone; the number is always formatted with `formatPct(value, true)` from `lib/format.ts`. It accepts `number | null`, and **`null` renders an em-dash in `text-muted`** — three distinct states, deliberately: a flat week is `Minus 0%`, a present week with no baseline is a `text-muted` dash, and an absent week's cells are `text-faint` dashes. Do not collapse the last two: `text-faint` (#586478) on the card gradient is ~3.0:1, which fails WCAG AA at the ~10.5px `text-sm` becomes under the global 75% root font size, while `text-muted` (#8a98ad) is ~6.4:1. What the percentage *measures* is the caller's choice, and it currently differs by surface: the member page's Week-by-Week History compares total damage against the member's most recent prior present week (`deltaPct` in `lib/compute.ts`) — its column is headed **Dmg vs Prev Week** rather than "Trend" precisely because the badge alone can't disclose that — while the Hydra/Chimera clash tables and the per-clash cards compare damage-per-key against the previous global week.

## Rules of use

- **No hardcoded hex colors in components.** New colors become tokens in `@theme` first; new surface treatments become primitives.
- Global `html { font-size: 75% }` scales all rem sizing — use Tailwind `text-*` classes, never px compensation.
- Numeric metrics use `tabular-nums`; section headings use `font-display`.
- Icons: lucide-react. Charts: Recharts, filled with the clash accent tokens.
- Body background carries a fixed radial "lighting" glow — components should not add competing page-level backgrounds.

Reference implementations: `components/ClashCard.tsx` (card + inset + accent theming pattern), `components/PerformanceTable.tsx`, `components/WeeklyBarChart.tsx`, `components/MemberCell.tsx` (the canonical member avatar + linked-name cell — every table that shows a member renders it; `formerStyle="badge"` shows the Former pill, `"muted"` dims the name instead, and `isBenched` adds the shield — see **Name-adjacent status marker** above before adding a third).

## Overview

Web dashboard for a RAID: Shadow Legends clan's **Hydra Clash** and **Chimera Clash** performance — per-member keys used, damage, participation, and week-over-week trends. It runs on the owner's machine (`npm run dev`) and **deployed on Vercel** (per the owner's report, `main` is the production branch, auto-deploying on push — not verifiable from the repo, so treat it as reported rather than measured); the database is hosted. **Reads are public; every write is admin-only** — one account, signed in at `/login`, authorized by an `ADMIN_EMAIL` match (`docs/reference/auth.md`).

Stack: **Next.js 16 (App Router, TypeScript) · Tailwind CSS v4 · Recharts · lucide-react · Supabase Postgres 17 via `postgres` (postgres.js)** over a pooled (`:6543`) URI with `prepare: false`, plus **Supabase Auth via `@supabase/ssr`** (`2.112.3` / `0.12.4`) for sign-in only — never for data. The app reads **exactly four** environment variables: the connection URI (`DATABASE_URL`, else the integration's `POSTGRES_URL`), `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `ADMIN_EMAIL`. **A Vercel deployment needs no manual `DATABASE_URL`**; `POSTGRES_URL_NON_POOLING` and `POSTGRES_PRISMA_URL` are deliberately never read. **One Supabase project serves production, every preview and local dev**, so a preview writes production data. See `docs/reference/deployment.md`.

> **Superseded — SQLite / libSQL / Turso.** Phase 2's Supabase Postgres port superseded the *locked* **Turso** path — a hosted drop-in for the local **SQLite** `data/clash.db` via **`@libsql/client`**: package uninstalled, no database file read at runtime, no dual-engine SQL constraint. Engine names spelt out so that vocabulary greps here.

## Structure

- `app/` — routes: `/` (overview), `/hydra`, `/chimera` (per-clash detail), `/timeline` (weekly totals), `/members` + `/members/[memberId]` (roster/detail), `/settings` (clan info, data management, import tab), `/import` (**not a page** — a two-line `redirect("/settings")` answering **307**; kept only so old links don't break — `app/import/page.tsx:5`), `/login` (**deliberately absent from the sidebar** — `docs/reference/auth.md`).
  **Two page shells, and they now differ — deliberate as of 2026-08-17, not drift.** `/` scrolls like an ordinary page (`app/page.tsx:94`, plain `flex flex-col gap-6 p-6`; Clan Performance + Black List split at **`2xl`**, not `xl` — `app/page.tsx:136`), while `/hydra` and `/chimera` keep the fixed-viewport lock (`components/ClashDetailView.tsx:66`). Consequence: the week picker scrolls away on `/` and is permanently visible on the other two. Route dynamism is `.claude/rules/rendering.md`; layout is `docs/reference/design-system.md`.
- `app/api/` — the write surface: `import`, `backup`, `restore`, `reset`, `members/[memberId]/results`, `members/[memberId]/avatar`, `members/[memberId]/bench`. **All seven are admin-only:** each handler opens with `requireAdmin()` as the first statement of its body and returns a frozen 401 to anyone else, issuing no database query. `backup` is gated as an **exfil** route, not a read. `avatar` and `bench` are **member metadata**, not ingest: they go through `lib/members.ts`'s two direct-SQL writers, never `persist()` (`docs/reference/data-pipeline.md`).
- `proxy.ts` (repo root) — token refresh, nothing else. **The file convention is `proxy`, not `middleware`, in this Next version; a `middleware.ts` is silently ignored.** Never blocks; no-ops when the Supabase env vars are absent.
- `app/login/` — `page.tsx` + `LoginForm.tsx` + `actions.ts`. `actions.ts` holds the **only** `"use server"` functions in the repo (`signIn`, `signOut`); no data write goes through a Server Action, so `requireAdmin()` stays the single choke point.
- `components/` — **28** UI components in the gestal.gg aesthetic; all styling flows from the 13 tokens/primitives in `app/globals.css`. (Measured `ls components/*.tsx | wc -l`, 2026-08-18. It has drifted twice, both times because a batch landed without this line moving — re-measure, never estimate.) Three structural facts: **two components start a `?week=` change** — `TopBar.tsx` and `TimelineStrip.tsx` — and both must push through `WeekTransition.tsx` (`grep -rn 'set("week"' components/` must return exactly those two); **one is shared by six tables** — `Pagination.tsx` owns the ten-rows-a-page control and the clamped page index for Clan Performance, its Total tab, the Black List, the clash Player Breakdown and both `/members` cards; and **`RosterTable.tsx` + `BenchedRosterTable.tsx` are `"use client"` leaves carved out of `app/members/page.tsx`** so the paging position can be client state without the page reading `searchParams` again — the page stays a server component, computes every row, and hands the second leaf the benched subset of the same rows (benching removes nobody from the Roster). Patterns, primitives and the pagination contract: `docs/reference/design-system.md`.
- `lib/` — the seams:
  - **Read path:** `data.ts` `loadDataset()` reads members / weeks / clash_results / clash_meta from Postgres → `compute.ts` derives all metrics (data-source agnostic). Its derivations split into two families the UI must keep apart: **week-scoped** (`getOverview`, `getPerformance`, `getKeyUsageSummary` — they take a `weekNumber`, and their surfaces show placeholders during a week change) and **all-weeks** (`getTimeline`, `getAllWeeksTotals`, and `getBlackList(ds)` at `lib/compute.ts:381` — no week argument, so its surfaces must not swap). `data.ts`'s four row mappers are the **single coercion boundary** (Postgres `bigint` reads back as a JS string; every numeric field is wrapped in `Number(...)`). It exposes `DataSource = "postgres" | "demo"` and falls back to `mock-data.ts` (weeks 20–24) **only** when `databaseUrl()` is null or the error code is `42P01`; every other failure rethrows to `app/error.tsx`, and a reachable-but-empty database renders genuinely empty.
  - **Black List semantics — this file is their only home, so read it before changing `getBlackList`.** The window counts only *fully imported* weeks: `isWeekComplete` (`lib/compute.ts:350`) requires rows for both clashes, and the window is `sortedWeeks(ds).filter(isWeekComplete).slice(-windowSize)` (`:385-387`) — filter *then* slice, so the window stays its full width by reaching back rather than shrinking. A half-imported week is therefore byte-identical to an absent one, and the roster gate reads off the newest **judged** week (`:411-414`), not `activeMemberIds`. That is an owner decision, not an optimisation: the routine two-clash-at-a-time import always leaves a mid-import week on a publicly readable board, and judging it manufactures misses. **One exception (2026-08-18):** an admin-excused member (`members.is_benched`) is dropped at that gate (`:443`), leaving `rows` **and** `membersJudged`. `BlackListResult` carries **`membersJudged`** (`lib/types.ts:167`) so the UI can tell "measured, all clear" from "nobody measurable yet". Four thresholds in `lib/constants.ts:19-38`; three view types at `lib/types.ts:134`/`:148`/`:158`.
  - **Write path — two payload builders, one writer.** The import paths go `parse.ts` → `import.ts` normalizers (pure, client-safe) → `persist.ts` `persist(payload, "upsert" | "replace")`, one transaction. The member week edit goes through `results.ts`, which imports only *types* from `import.ts`, runs **no** normalizer and hand-builds its payload. Writing this as a single three-stage funnel is the error that has already propagated into three docs. `.claude/rules/data-pipeline.md`.
  - `db.ts` — one pool, four exports (`Db`, `databaseUrl()`, `getDb()`, `closeDb()`), a `globalThis` singleton with `prepare: false` and `max: 3`. **`max` is a correctness bound** — exceeding it deadlocks against the transaction pooler, so a multi-query read runs inside one `begin("read only", …)`. Full rules, including why `databaseUrl()` is a loop and not `a ?? b`: `.claude/rules/database.md`.
  - **Auth path (the whole authorization surface):** `supabase/server.ts` `createServerSupabase()` (used for `auth.*` **only** — no `.from(`, no `/rest/v1` anywhere) → `auth.ts`, which exports exactly `isAdmin()` (never throws, wrapped in React `cache()`) and `requireAdmin()` (**returns** a 401 `NextResponse`, never throws). `lib/supabase/client.ts` **deliberately does not exist**; the publishable key never enters the bundle. `isAdmin()` is read in exactly two pages and **never in `app/layout.tsx`** — `cookies()` is request-time, so reading it there would opt every route into dynamic rendering. `docs/reference/auth.md`.
  - `week.ts` (UTC clash schedules), `types.ts`, `format.ts`, `constants.ts`, `backup.ts`, `members.ts`, `results.ts`, `seed.ts`.
- `supabase/migrations/` — numbered, forward-only SQL, applied in filename order by `npm run db:migrate` (safe to re-run). An applied migration is never edited; a change means a new numbered file. **0001–0003 are applied** — re-measured read-only 2026-08-18: live `members` has `is_benched` and one row set, so Bench and Restore no longer refuse. (An unmigrated clone still does; both surfaces name the fix.)
- `scripts/` — CLI entries (`db-migrate`, `seed`, `import-csv`, `import-json`); each imports `scripts/lib/load-env.ts` first and closes the pool so the process exits.
- `data/` — tracked samples: `sample-import.csv`, `sample-week-flat.json`, `sample-week.json`. The owner's archived SQLite files and a stale `active-db.json` sit here untracked and are read by nothing. `Database/` — tracked real exports, currently `test-week.json`, a flat array; the shape `lib/import.ts:107` cites. `Assets UI/` — design references.
- `docs/` — `README.md` is the hub; `docs/engineer-onboarding.md` and `docs/user-guide.md` are the two human entry points; `docs/reference/{auth,data-pipeline,deployment,design-system}.md` are the living references; `docs/build-log.md` is append-only history and `docs/tasks/` is the runtime work queue, **not documentation — nothing links to it**.

## Key entities / modules

- **Dataset** (from `loadDataset()`) is the architecture seam between storage and UI — pages consume it, `compute.ts` derives from it, and its shape is identical in every data state. No file outside `lib/data.ts` compares `getDataSource()` against a storage literal; call sites test `=== "demo"` / `!== "demo"`.
- **Clash semantics:** Hydra = 3 keys/member, Wed→Wed (UTC); Chimera = 2 keys/member, Fri→Thu (UTC); both clashes of week *N* share a calendar week. Dates are derived, never user-entered.
- **Ingest semantics:** three entry points, one writer. In-app JSON import = replace of its `(week, clash)`; legacy nested JSON = upsert; CSV file (`npm run import`) = upsert; member week edit = upsert of that member's two clash rows. Damage accepts a number, `"16.61B"` shorthand, or `null` (benched → 0). **The terminal is not uniformly the "safe" half:** `npm run import:json` picks its mode from the file's shape, so a **flat array replaces** (`scripts/import-json.ts:44`) and only the nested `{ week, clashes }` object upserts (`:50`).

## Open unknowns / blockers

- **No test suite** — verification is `npm run build` + manually exercising the affected page. A future order could add one.
- **Preview deployments read and write production data.** One Supabase project, so every preview inherits the same URI; a preview's Import/Restore/Reset hits the clan's real rows (416 `clash_results` across 30 members / 7 weeks). Writes still need the admin session, so the risk is the owner acting on a preview URL believing it is a sandbox. `docs/reference/deployment.md`.
- **Free tier: no automated backups, and a project pauses after ~1 week idle.** `GET /api/backup` is the only backup. A paused project correctly reaches `app/error.tsx` (not demo mode) — the case most likely to tempt someone into widening the demo fallback.
- **The deployed runtime is unmeasured from this side.** No agent has Vercel access, so every deploy-side fact is the owner's report; only the code and the local build were measured.
- **The signed-in half of the login wall ships unexercised.** Nobody but the owner has the password, so the cookie write, session persistence, Sign out and every admin-visible affordance in its rendered state were never run. The owner's acceptance test (sign in → edit a week → export a backup → sign out) closes it. `docs/reference/auth.md`.
- **`/login` has no navigation entry point** outside `/settings` and the member pages. Accepted as designed — recorded so nobody "repairs" it with a sidebar link without asking.
- **`Assets UI/`** — design references exist but their intended workflow (manual vs. Figma-driven) is not established.
- **OPEN BUG — a `TrendBadge` safeguard is defeated at one call site** (found 2026-08-13, re-verified 2026-08-18). `components/TrendBadge.tsx:4-5` documents that `value === null` means "no comparable baseline" and renders an em-dash "instead of a misleading flat 0%", and the member page passes `null` through intact (`lib/compute.ts:286`). The clash tables coerce it first: `deltaPct(thisPerKey, prevPerKey) ?? 0` at **`lib/compute.ts:172`**. So on `/hydra` and `/chimera` a member with no prior week renders **`0%`**, indistinguishable from "unchanged", and the CSV export inherits the same `0`. The fix is letting `trendPct` be `number | null` through `ClashTable`; the type ripple is why it is recorded rather than done. User-visible, documented in `docs/user-guide.md`.
- **OPEN BUG — `npm run import` with no argument dies on a raw `ENOENT`** (re-verified 2026-08-18). `scripts/import-csv.ts:12` defaults the positional to `data/import.csv`, **a file this repo does not ship**; `readFileSync` throws before any usage message. Ship the default, point it at `data/sample-import.csv`, or print usage.
- **OPEN BUG — `components/TopBar.tsx:129-144` drops keyboard focus at the ends of the week range** (found 2026-08-17, unowned by every task so far). Both week chevrons carry the native `disabled` attribute (`:131`, `:139`), and a disabled element cannot hold focus, so stepping to the newest or oldest week *while the chevron has focus* drops focus to `<body>`; the chevron is then skipped by Tab entirely. `components/Pagination.tsx` inherited this shape and **fixed it** in the same order, so the fix is two attributes and two guards — but `TopBar` is the week-transition seam and belongs to whoever owns that. **Do not copy `TopBar`'s chevrons as the pattern**; the corrected form is `docs/reference/design-system.md`'s Pagination entry and `.claude/rules/ux.md`'s third hide-don't-disable case.
